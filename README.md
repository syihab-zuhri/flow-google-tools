# Flow Studio

Flow Studio is a local-first workstation for composing, reviewing, and exporting coherent long-form AI video workflows. It combines a visual node editor with continuity tooling, FFmpeg media processing, project persistence, and a local credential-vault lifecycle.

The repository name is `flow-google-tools`; the product name is Flow Studio.

## Current Features

- Visual canvas built with React Flow for Prompt, Image Reference, Video Reference, and Video Generation nodes.
- DAG validation with port compatibility checks, cycle detection, topological execution order, selection state, and undo/redo history.
- Atomic `.flowproj` save/load persistence with typed Rust/Tauri IPC bindings generated by `tauri-specta`.
- Continuity pipeline with prompt carry-over, style locking, last-frame extraction, and retry handling.
- FFmpeg concat, preview, segment markers, MP4/WebM export, and resolution presets for Original, 1080p, and 720p.
- Local vault lifecycle with master-password setup, unlock/lock, cooldown after failed attempts, inactivity auto-lock, and reset flow.
- Vitest, Rust tests, ESLint, TypeScript, Prettier, Storybook, Clippy, and anti-slop quality gates.

## Integration Boundary

External generation is supported through an official documented provider integration when one is available, or through explicit manual handoff. The project does not collect Google browser passwords, import cookies or private session tokens, replay private endpoints, bypass CAPTCHA or anti-automation controls, or rotate accounts to evade provider quotas.

The current workflow is:

1. Build the prompt and reference pipeline in Flow Studio.
2. Generate through the provider's official UI or supported API.
3. Import the resulting media into the project.
4. Use continuity, preview, stitching, and export inside Flow Studio.

## Tech Stack

- Desktop shell: Tauri 2.x
- Frontend: React 19, TypeScript, Vite, and `@xyflow/react`
- Native core: Rust
- Persistence: SQLite
- Media processing: FFmpeg
- Testing: Vitest, Testing Library, Rust tests, and Storybook

## Requirements

For browser development:

- Node.js
- pnpm `10.18.0`

For the native desktop build:

- Rust stable toolchain
- Tauri 2 system dependencies
- Microsoft WebView2 on Windows
- FFmpeg available to the application for media operations

See `docs/ENVIRONMENT.md` for the full environment specification.

## Getting Started

Install dependencies:

```bash
pnpm install --frozen-lockfile
```

Run the browser development server:

```bash
pnpm dev --host 127.0.0.1
```

Open `http://127.0.0.1:1420/` in a browser. Browser mode is intended for frontend and canvas development; native Tauri commands require the desktop shell.

Run the native desktop application:

```bash
pnpm tauri dev
```

Build the frontend:

```bash
pnpm build
```

## Verification

Run the frontend checks:

```bash
pnpm lint
pnpm typecheck
pnpm test:coverage
pnpm format:check
pnpm slop:scan
```

Run the Rust checks:

```bash
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --offline -- -D warnings
cargo test --workspace --offline
```

Build Storybook:

```bash
pnpm build-storybook
```

## Security and Local Data

Project files, generated media, logs, and the local SQLite database are intended to remain on the user's machine. Do not commit `.env` files, credentials, browser session data, private keys, generated projects, media assets, or local database files. The repository `.gitignore` includes the primary local-state and secret-file patterns.

Read `docs/SECURITY.md`, `docs/API.md`, and `docs/TASKS.md` for the security boundary, IPC contracts, and implementation history.
